# تاسك 4 — واجهة Terminal تفاعلية

## التشغيل

افتحي هذا المجلد كمشروع في IntelliJ واختاري JDK 21.
من Terminal داخل المشروع:

```powershell
.\gradlew.bat -PcliOnly --console=plain run --args="--demo"
```

`--demo` يعمل دون Supabase: مسارات تجريبية بخوارزمية Dijkstra الموجودة، بيانات تدريب KNN مصطنعة، وتتبّع محاكى. بيانات التدريب ليست سجلات تاريخية حقيقية، وهذا ليس تسليم العضوين 2 و3.

القائمة:

```text
1 Route | 2 Classify | 3 Start telemetry | 4 Stop telemetry | 0 Exit
```

جرّبي بالتسلسل:

1. اختاري `3`: تظهر إحداثيات وسرعة ووقود كل ثانية، والقائمة تبقى متاحة.
2. اختاري `1` ثم `WH-001` ثم `WH-003`: يظهر المسار عبر `WH-002` بمسافة 155 كم.
3. اختاري `2` ثم `31.9 35.2 5`: يظهر القطاع المتوقع من بيانات التدريب التجريبية.
4. اختاري `4`: يتوقف التتبّع، مع بقاء القائمة.
5. اختاري `0` أو `exit`: تلغى جلسة البرنامج وكل العمليات التابعة لها.

اكتبي كل إجابة في سطر ثم Enter. استخدمي نقطة للأعداد العشرية. مؤشر الانتظار يظهر أثناء حساب المسار فقط؛ الحساب التجريبي سريع وقد ينتهي قبل ظهور المؤشر.

قراءة الإدخال تستخدم polling للبايتات المتاحة مع `delay`؛ لا تنشئ thread إضافياً ولا تحجز worker أثناء انتظار الكتابة. الخروج المضمون يكون بالأمر `0` أو `exit`. انتهاء ملف إدخال redirected وحده لا يمكن اكتشافه بشكل موثوق باستخدام `available()`، لذلك أي script يجب أن يرسل أمر الخروج. اختبارات الـshell تستخدم Terminal قابلاً لتمثيل نهاية الإدخال.

## كيف تفهمي الكود

- `src/main/kotlin/presentation/cli/InteractiveShell.kt`: ابدئي هنا. حلقة تعرض القائمة، تقرأ الاختيار، ثم `when` يشغّل الوظيفة المناسبة.
- `ConsoleTerminal.kt`: قراءة الإدخال وطباعته، مع تعليق coroutine أثناء الانتظار.
- `CliServices.kt`: عقود تربط الواجهة بحساب المسار والتصنيف والتتبّع.
- `CliLauncher.kt`: يربط الواجهة بالخدمات المسجلة في Koin.
- `DemoShell.kt`: خدمات العرض التجريبي فقط.
- `presentation/Main.kt`: يشغّل الـCLI افتراضياً؛ `--demos` يشغّل عروض المشروع القديمة.

`launch` يشغّل الأمر كعملية تابعة للجلسة، فيستمر استقبال القائمة. `Flow.collect` يطبع التحديثات عند وصولها. `cancelAndJoin` يوقف التتبّع وينتظر تنظيفه. عند الخروج نلغي parent session فتُلغى أوامرها والمؤشر والتتبّع. الأخطاء التشغيلية تظهر كرسالة؛ `CancellationException` يعاد رميها حتى يظل الإلغاء صحيحاً. `supervisorScope` يبقي القائمة عاملة إذا فشل أمر مستقل.

## الربط مع الفريق

حساب المسار مربوط بالفعل بـ `FindOptimalPathUseCase`. التشغيل الحقيقي يحتاج إعدادات Supabase الموجودة في المشروع:

```powershell
.\gradlew.bat -PcliOnly --console=plain run
```

يتفق العضوان 2 و3 معك على المدخلات والنتائج، ثم يسجلان adapters في Koin. هذا مثال توضيحي؛ أسماء دوالهما تعتمد على تسليمهما:

```kotlin
single<PackageSectorClassifier> {
    val classify = get<ClassifyPackageSectorUseCase>()
    PackageSectorClassifier { features ->
        // Map features to the actual use case input, then map its result to a sector name.
        classify(/* actual input */).toString()
    }
}

single<FleetTelemetry> {
    val track = get<TrackActiveFleetUseCase>()
    FleetTelemetry {
        track(/* actual filters */).map { event -> event.toString() }
    }
}
```

المثال ليس ملف Kotlin جاهزاً للنسخ: توقيعات العضوين غير موجودة في النسخة المرفقة. بدون تسجيلهما، يظهر للمستخدم سبب عدم توفر الخدمة، وتستمر القائمة.

## الدراسة بالترتيب

1. 8.01 لفهم معنى blocking وthread إن كانت جديدة عليك.
2. 8.02 لفهم `suspend` و`launch` و`delay`.
3. 8.03 لفهم scope وفرق IO وDefault.
4. 8.04 لفهم علاقة parent/children والإلغاء؛ هذا أساسي للخروج النظيف.
5. 8.05 لفهم انتظار النتائج والأخطاء؛ تستخدمين نتيجة الدالة المعلقة، وقد ترين async/await في شغل الفريق.
6. 8.07 لفهم Flow وcollect والتتبّع.
7. 8.06 لفهم اختبارات الوقت الافتراضي والإلغاء.
8. 8.08 أقل ارتباطاً بالقائمة الحالية، لكنه مطلوب ضمن تحضير الأسبوع.

من الكتب: فصل 12 من Grokking لفهم مدخلات ومخرجات KNN، وClean Code 17 لتنظيم الدوال والأسماء. بقية الفصول المذكورة مطلوبة للنقاش الأسبوعي، ولو لم تُستخدم مباشرة في تاسك 4.
